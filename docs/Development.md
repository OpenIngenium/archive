# Development

See [Configuration](./Configuration.md) for environment variables and [Testing](./Testing.md) for the test workflow. This page covers running the service itself.

## Prerequisites

- Node.js matching `.nvmrc` (`22.23.4`); `package.json` `engines` enforces `>=22.0.0 <23`.
- A reachable ArangoDB instance; point `ARANGODBURL` at it.

## Install

```bash
npm install
```

Runtime dependencies (`package.json`): `arangojs` 7.8.0, `body-parser`, `deepcopy`, `express`, `express-interceptor`, `extend`, `js-yaml`, `jsonwebtoken`, `lodash`, `remove-blank-lines`, `swagger-tools` 0.10.4, `uuid`, `winston`. Dev dependency: `jest`.

## Run locally

```bash
npm start          # node index.js — requires a reachable ArangoDB at $ARANGODBURL (or localhost:8529)
```

`index.js` calls `api/base_funcs.js#init_db()` before starting the HTTP server; if ArangoDB is unreachable it retries (10 attempts, 4 s apart — see [Configuration](./Configuration.md#required-vs-optional-in-practice)) and then logs an error via the `init_db().then(..., (err) => log.error(err))` rejection handler in `index.js` — the process does **not** exit non-zero on this failure, it simply never starts the HTTP listener. On success, the server listens on port `8010` (hardcoded `serverPort` in `index.js`, not configurable via environment variable):

```text
Your server is listening on (http://localhost:8010)
Swagger-ui is available on http://localhost:8010/docs
```

## Verify it's running

```bash
curl http://localhost:8010/api/v5/health
# {"status": "OK", "message": ""}
```

Interactive docs: `http://localhost:8010/docs` (Swagger UI, generated by `swagger-tools` from `api/swagger.yaml`).

## npm scripts

| Script | Command | Purpose |
|---|---|---|
| `npm start` | `node index.js` | Run the service |
| `npm test` | `jest` | Run the Jest unit suite once |
| `npm run test:watch` | `jest --watch` | Re-run tests on file change |
| `npm run test:coverage` | `jest --coverage` | Run tests with coverage, enforcing the thresholds in `jest.config.js` (see [Testing](./Testing.md)) |

`package.json` does not define separate `lint`, `format`, or `typecheck` scripts, and there is no ESLint/Prettier/TypeScript configuration file anywhere in the repository — linting/formatting/type-checking are **not currently part of this project's tooling** (not merely undocumented; there is no config for any of them to run against).

## Building the Docker image manually

```bash
docker build -t ingenium_archive:local .
```

`Dockerfile`:
```dockerfile
FROM node:22.23.4-slim
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci --omit=dev
COPY . /app
USER node
ENTRYPOINT ["node", "index.js"]
```

The base image is the public `node:22.23.4-slim` image. `npm ci --omit=dev` installs only production dependencies (Jest is excluded from the image). The container runs as the non-root `node` user.

## Debugging

The repository does not define a debug launch configuration (no `.vscode/launch.json`, no `--inspect` npm script). To attach a debugger locally:

```bash
node --inspect index.js
```

For request-level debugging, set `LOG_LEVEL=trace` (see [Configuration](./Configuration.md)) to get the most verbose logging, including `log.trace` calls scattered through `api/base_funcs.js`/`api/node_funcs.js`/`api/procedure_funcs.js` at nearly every branch of the graph-mutation functions.
